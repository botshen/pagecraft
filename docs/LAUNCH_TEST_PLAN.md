# 上架前实测计划：10 个真实网站生成与自愈成功率（零服务端架构）

**目的**：发布前确认 PageCraft 在 **100% 纯本地客户端架构（零服务端、零遥测）** 下的真实网站改造成功率、多模态视觉理解（Vision）与闭环自愈（Auto-Heal）表现。**成功率低于 60% 不上架**，先优化选择器提取与闭环自愈提示词。

## 准备

1. **配置任一本地 / 自有算力引擎**（推荐至少覆盖 2 种模式交叉验证）：
   - **Chrome 内置 AI（Gemini Nano）**：在 Chrome 138+ 开启端侧 Prompt API，于扩展「设置」切换为 *Chrome Built-in AI (Gemini Nano)* 并确认状态可用（零配置离线）。
   - **本地离线模型（Ollama / LM Studio）**：终端启动 `OLLAMA_ORIGINS="chrome-extension://*" ollama serve`，在扩展「设置」选择本地端点（如 `http://localhost:11434/v1`）。
   - **自有密钥直连（Direct BYOK）**：在扩展「设置」填入 OpenAI / Anthropic / DeepSeek / OpenRouter API Key，浏览器直连验证（同时验证纯文本模型如 `deepseek-chat` 在开启 Vision 时的 HTTP 400 自动降级重试）。
   - **本地编程智能体桥接（`pagecraft-mcp`）**：在扩展「设置」开启 `ws://127.0.0.1:17321`，运行 `pnpm mcp` 并用 Claude Code / Cursor / Codex 调用工具验证实时改页。
2. 执行 `pnpm build`，在 `chrome://extensions` 打开开发者模式，「加载已解压的扩展程序」，选择 `.output/chrome-mv3`。
3. 在扩展详情页打开 **允许用户脚本（Allow User Scripts）**（JS 用例需要；CSS 用例免开此开关）。
4. 打开 DevTools Network 面板确认：**零请求发往任何 PageCraft 官方服务器、零后台遥测或反馈打点**。

## 判定标准

- ✅ **一次成功（含自动闭环自愈）**：首次点击「生成改造」（包含 `Auto-Healed ✓` 自动 0 命中自愈重试后命中目标），点「启用并保存」后效果符合预期
- 🟡 **手动微调成功**：经过 ≤ 2 轮对话微调或点击本地「自动校准 / 微调」按钮后符合预期
- ❌ **失败**：2 轮后仍不符合预期、报错，或者页面核心交互被改坏
- **刷新页面与 SPA 切页后再看一次**，确认改造能持久生效且随时可在「我的改造」一键关闭还原

**成功率** = (✅ + 🟡) / 10。另外单独记录 ✅ 率以及 `Vision` / `Auto-Healed ✓` 徽章触发情况。

## 失败用例排查方向

- 选择器 0 命中且未自愈：检查 `lib/picker/selector.ts` 是否过滤了动态哈希类名，以及闭环自愈（Auto-Heal）二次提取的实时 DOM 地标是否包含目标容器
- 纯文本模型开启 Vision 报错：确认 HTTP 400/415/422 自动回退纯文本请求逻辑生效
- 生成的 JS 在 SPA 里只生效一次：检查生成代码是否使用幂等标记与 `MutationObserver`
- 返回的 JSON 解析失败：检查 `parseGeneratedMod` 与 `extractJsonString` 容错逻辑
